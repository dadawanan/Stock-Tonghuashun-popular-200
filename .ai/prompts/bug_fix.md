# Prompt — Bug 修复

请用「复现 → 根因 → 修复 → 回归 → 文档」五步法处理。

## 你必须按顺序产出

1. **复现**：列出最小可重现步骤（命令 / 请求 / 数据），并附上当前的错误日志或异常栈。
2. **根因**：用 1–3 句话写清「为什么错」。**严禁**只描述现象。
3. **修复**：
   - 给出 diff（或具体改动文件 + 函数）
   - 改动**必须**与 `system_rules.md` 一致；如发现规则与实现冲突，**必须**先指出
   - 不要顺手做无关重构；如确有必要，新开一个 `refactor.md` 提示词
4. **回归测试**：
   - 给出新增 / 修改的测试用例（路径 `web/tests/`）
   - 或描述手工验证步骤（含预期输出）
5. **文档同步**：
   - 在 `changelog_ai.md` 追加 1 条「为什么修」
   - 如修了行为契约，同步改 `api_spec/<module>.md`
   - 如发现常踩坑点，沉淀到 `system_rules.md` 或本目录新增一个 `notes/<topic>.md`

## 强校验

- [ ] 没有引入新的 print 调试语句
- [ ] 没有静默 `try/except: pass`
- [ ] 没有改其他模块的副作用未在 changelog 解释
- [ ] 修复完成后，`logger.error(..., exc_info=True)` 能让运维清楚定位
- [ ] 没有为单点小逻辑额外抽 `_xxx` 私有函数 / 新建 `*_helpers.py`、`*_utils.py`（除非已被 ≥ 2 处复用，或用户明确要求；详见 `system_rules.md` 第 14 节）
