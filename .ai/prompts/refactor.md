# Prompt — 重构（拆模块 / 改架构）

重构是高风险操作，**必须**先文档、后代码。

## 你必须按顺序产出

1. **现状摘要**：受影响文件清单 + 当前耦合关系（可 ASCII 图）。
2. **目标摘要**：重构后的目录布局 / 调用关系 / 取舍理由。
3. **影响面**：
   - 公开 API 是否改变？（路径、状态码、响应体）
   - 数据库表 / Redis 键 / 队列名是否改变？
   - 启动顺序 / 后台线程是否改变？
4. **迁移步骤（小步快跑）**：把一次大重构拆成多个可独立合入的 PR，每一步都能编译运行。
5. **验证方案**：
   - 单测 / 集成测试 / 手测脚本
   - 关键链路压测（如检测主链路）
6. **文档同步（必做）**：
   - `architecture.md` 图示与流程
   - `api_spec/*.md` 一一比对
   - `changelog_ai.md` 追加「为什么这么做」+「权衡」

## 强校验

- [ ] 没有偷偷改公开 API（除非显式批准）
- [ ] 没有引入循环依赖（`app/services/X` 不允许 import `app/routes/...`）
- [ ] 没有把业务字段移进 `core/`（`core/` 只放进程级单例）
- [ ] 重构完文档先于代码合入，否则 reject
- [ ] 没有把单点小逻辑（list 统计 / 字段重命名 / 字符串拼接等）拆成只被 1 处调用的 `_xxx` 私有函数或独立 helper 文件，造成无谓的函数 / 文件碎片化（详见 `system_rules.md` 第 14 节）
