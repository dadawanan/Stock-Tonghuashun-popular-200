## HIGH PRIORITY — 影响实盘使用

### 1. 滚动前进优化（Walk-Forward Optimization）

**现状**：`optimizer.py` 只有网格搜索，在同一时间段训练+测试，容易过拟合。

**建议**：实现滚动窗口优化：
```
|---训练窗口1---|---测试1---|
      |---训练窗口2---|---测试2---|
            |---训练窗口3---|---测试3---|
```
取各窗口测试结果的平均值作为策略评价。

### 2. ATR 止损（代码缺失）

**现状**：`BacktestConfig.atr_stop_multiplier` 字段已定义，但 `backtest_rules.py` 的 `check_stop_loss()` 从未读取它。只有固定百分比止损和追踪止损在生效。

**修复**：在 `check_stop_loss()` 中加入 ATR 止损逻辑：
```python
if config.atr_stop_multiplier and atr_value:
    atr_stop = entry_price - atr_value * config.atr_stop_multiplier
    if current_price <= atr_stop:
        return True, "ATR止损"
```

### 3. 市场环境识别（Market Regime Detection）

**现状**：所有策略在牛市/熊市/震荡市用相同参数。

**建议**：基于大盘指数（沪深 300）判断环境：
- **牛市**：MA50 > MA200，放宽买入条件
- **熊市**：MA50 < MA200，收紧买入或暂停
- **震荡市**：均值回归策略加权

可在 `StrategyContext` 中添加 `market_regime` 字段。

### 4. 最大回撤强制执行

**现状**：`daily_settlement()` 中回撤超限只打日志，不暂停交易。

**建议**：回撤超限时：
- 禁止新开仓
- 可选：强制平仓
- 通知用户

### 5. 波动率调整仓位

**现状**：所有股票用相同的 `max_position_pct`（默认 20%）。

**建议**：高波动股票减仓，低波动股票加仓：
```python
volatility = atr / close
position_pct = base_pct * (target_volatility / volatility)
```

### 6. 板块集中度限制

**现状**：同一板块可以买满仓位，无分散约束。

**建议**：添加 `max_sector_pct`（如单一板块不超过 40%）。

## MEDIUM PRIORITY — 提升系统健壮性

### 7. 样本外验证

在回测中支持 train/test split，自动计算样本内外的收益差异，检测过拟合。

### 8. 更多绩效指标

| 指标 | 说明 |
|------|------|
| Sortino 比率 | 只惩罚下行波动 |
| Calmar 比率 | 收益/最大回撤 |
| Alpha/Beta | 相对基准的超额收益和系统性风险 |
| 信息比率 | 超额收益/跟踪误差 |
| 月度/年度收益分布 | 按月/年拆分收益 |
| 回撤持续时间 | 从回撤到恢复的天数 |

### 9. 策略间相关性分析

计算各策略信号的收益相关性，避免高度相关的策略叠加（分散化失效）。

### 10. 告警系统

- 止损触发时通知（邮件/Webhook）
- 信号生成时通知
- 回撤超限时通知

### 11. KDJ 指标存储

`indicators.py` 已实现 KDJ 计算，但未写入 `stock_indicator` 表。

### 12. 基本面数据

实时行情已获取 PE/PB，但未存储也未在策略中使用。可添加估值策略（低 PE 买入等）。
